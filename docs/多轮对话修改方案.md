# 同一次通话的多轮上下文修改方案

上下文只保存在这一次 LiveKit Agent 任务里。不改 `himarket-rs` 的会话接口，也不把历史放到进程全局变量。

需要同时改两份相同入口：

- `livekit-agents/examples/himarket_voice/agent_main.py`
- `voice-agent-worker/agent_main.py`

## 1. 现状

`call_llm()` 每次只发送两条消息：系统提示，以及当前这一句用户文本。上一轮问过什么、模型回答过什么，都不会进入下一次请求。语音识别和语音合成只处理当前音频，这部分不用改。

## 2. 上下文放在哪里

在 `entrypoint()` 内、`process_turn()` 之外创建列表。每个房间一次 `entrypoint()`，所以不同 App、不同通话天然各有一份历史。

```python
history = [{
    "role": "system",
    "content": system_prompt or "你是语音助手。请结合本次通话里已经说过的话，用简短口语回答。",
}]
max_turns = 10
```

不要使用按 `session_id` 存在模块全局的字典。Worker 进程里会同时跑多个房间，全局字典容易串话，也没有房间结束时的清理点。

## 3. 修改 `call_llm()`

增加参数 `history: list[dict]`。请求体改为：

```python
body = {
    "model": llm_model,
    "messages": history,
    "max_tokens": 256,
    "temperature": 0.6,
}
```

函数内部不再自己组装 `system` 和 `user`。`session_id`、`tenant_id`、`api_key_id` 仍只放在请求头，用于标识和计费。

## 4. 每一轮怎么更新

`process_turn()` 保持现在的顺序：先识别，再调用模型，再合成。历史只在模型调用前后更新。

1. 识别出 `user_text` 后追加：`{"role": "user", "content": user_text}`。
2. 调用 `call_llm(..., history)`。
3. 调用成功后才追加：`{"role": "assistant", "content": reply_text}`。
4. 调用失败时弹出刚追加的用户消息，并使用现在的失败提示语。失败提示不写入历史。
5. 截断时保留下标 0 的系统消息，其余只留最近 `max_turns` 轮，也就是最多 `1 + max_turns * 2` 条。

`speaking_lock` 已经保证同一房间不会两轮同时改这份列表，所以不需要再加锁。

## 5. 不改变的边界

- 识别和合成仍只接收当前这一句文本或音频。
- 房间、Token、用量事件的隔离方式不变。
- 管理后台里的模型和租户配置不变。换模型只影响新会话；进行中的通话继续使用进入房间时的模型和这份内存历史。
- 通话结束或 Worker 重启后，内存历史消失。挂断后继续聊不在本方案内。那需要另按 `session_id` 把历史存进 `himarket-rs`。

## 6. 测试

用假的 HTTP 响应测试一个纯函数，不访问厂商。

- 连续两轮后，第二次请求的 `messages` 含系统提示、第一轮问答和第二轮用户话。
- 第二轮模型失败后，历史回到只含系统提示和第一轮成功问答。
- 超过 `max_turns` 时，系统提示仍在，最早的问答被丢掉。
- 两个模拟房间各有各的列表，房间 A 的话不会出现在房间 B 的请求里。
